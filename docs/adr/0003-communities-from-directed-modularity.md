# Communities come from directed modularity

Server-side community detection runs once per Crawl run, at completion, and its partition colors the Graph. Louvain is commonly described as an undirected method, and our Graph is directed (ADR 0001) — but direction is not a nuisance to project away: the networkx implementation computes modularity natively on directed graphs (Dugué & Perez 2015), reading in- and out-links as distinct signal. We feed the crawler's directed Graph to the library unchanged. No projection convention gets invented or defended, and a reciprocal Article-link pair contributes its full evidence instead of being collapsed. Detection uses a fixed random seed and the default resolution, so the same Graph yields the same partition for a pinned library version — in production and in tests.

**Considered Options**: undirected projection, unweighted or weighted by link count (rejected: invents a dedupe/weight convention and discards direction signal); python-louvain (rejected: undirected-only, unmaintained since 2024); igraph + leidenalg (rejected: heavy binary dependency for a ≤5000-node problem); client-side graphology-communities (rejected: detection is locked server-side at crawl completion).
